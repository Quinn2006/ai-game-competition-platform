## 模块与调用约束

|模块|当前行为|
|---|---|
|identity/authorization.mjs|默认拒绝未知动作、无身份及非 active 身份；公开读取须 published=true；作品按个人所有者或团队队长授权，团队成员仅可读；评委须获分配、技术审核通过、未提交且无本人/所属团队利益冲突|
|identity/profiles.mjs|作者公开投影只有 id、昵称、头像、简介；团队只有 id、名称、简介、成员昵称；本人资料额外返回邮箱，其他账号和管理员均不能借本人接口读取；学生材料不进入这些投影|
|identity/access.mjs|授权守卫；写入允许/拒绝审计后才返回，审计不可用时不放行；管理员敏感操作额外调用服务端验证器，危险操作还须显式确认并要求验证管理员密码；默认验证器永远拒绝|
|audit/security.mjs|参数化写入允许、拒绝、登录失败三种安全事件；校验 UUID、事件/结果配对和字段白名单；不接受密码、证明令牌、邮箱、学号、自由文本或任意 metadata|

角色矩阵测试覆盖游客、注册用户、作者、队长、成员、评委、管理员。作者、队长和成员按资源关系判定，不设置可由客户端自报的全局角色。管理员不自动绕过作品所有权；后续管理业务应使用显式管理权限。权限判定不代替赛事截止、成员变更审批、限流、封禁管理及评分事务约束。

所有模块输入是**可信服务端内部上下文**。后续 HTTP 层必须从验证后的会话加载账号状态和角色，从数据库加载目标作品、团队、评委分配；不得将请求体、查询参数或请求头中的 actor/roles/ownerId/memberIds 直接传入。数据库访问层须使用同一事务中的资源事实并做条件写入/锁定，防止授权后资源发生变化。当前没有身份表、资料数据库适配器、身份 HTTP 路由或页面，不能据此声称这些边界已端到端生效。现有服务仍只开放健康接口。

再验证适配器必须在服务端核对有效期、操作者、动作、资源、所需验证方式以及证明是否已被消费；有效期和具体认证方式等待 T-02。`confirmed` 只表示二次确认，绝不代替密码验证。认证接入前默认拒绝敏感及危险动作。守卫记录的是授权结果，不是业务操作成功；真正修改及其操作结果审计须在后续业务事务内一起提交。赛事决定审计必须另按 T-09 赛事档案期限保存，不可统一套用本次安全事件期限。

## 迁移、安全与运行

新增 `002_security_audit`，不修改已有 001 的内容/校验和。迁移清单扩展为顺序执行两条。新表 `platform.security_events` 使用 T-09 的安全事件六个日历月期限、UUID 引用、数据库约束及到期/请求索引，PUBLIC 无权限。尚无身份表，因此 actor_id 暂无外键；登录失败可不含 actor_id，避免把用户输入的邮箱存进审计。

down 拒绝删除非空安全审计表；每次仅回退最新迁移。CLI 保持开发/测试限制和既有确认要求，本轮没有执行数据库迁移或回退。仅有 expires_at 不等于自动清理：清理任务、保存例外、备份删除重放和实际数据库角色隔离仍待后续实现验证。
