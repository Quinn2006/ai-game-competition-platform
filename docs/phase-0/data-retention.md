# 数据分类、保留与清理验收矩阵

依据：独立计划书 §5 的 T-09 后续决定。这里记录产品约束，不构成法律适用性结论；上线前核查实际部署地区、未成年人身份/同意处理与隐私告知。广州大学学生参赛资格不代表学校主办或授权。

|类别 / 等级|最小数据与用途 / 可访问角色|起算与期限|清理任务 / 验收用例（待实现）|
|---|---|---|---|
|网络运行、安全事件 / 受限|事件、必要 IP/UA；安全调查人员及授权管理员|事件发生起 6 个月|RET-01：到期删除或不可逆匿名化；普通用户、客服不可读取；非安全用途不采 IP/UA|
|一般错误 / 内部|错误码、traceId、时间；运维|事件发生起 30 天|RET-02：到期清理；密码、令牌、完整身份材料不得写入；赛事管理决定转档案|
|普通 AI 客服 / 私密|答疑最小文本；本人及授权支持|会话结束起 90 天|RET-03：平台与供应商同步删除，供应商不训练且保存不超过平台期限|
|投诉 / 受限|正式投诉及处理证据；授权处理人|结案起 1 年|RET-04：普通客服转投诉后按结案时点；不无条件延长其他对话|
|普通试玩 / 私密|关联标识、作品、信号、风险；统计与授权核查|试玩结束起 30 天|RET-05：个人明细到期删除；只允许必要不可识别汇总继续保存|
|比赛试玩 / 受限|计分依据；赛事核查人员|最终发布、相关申诉结案较晚日期后 180 天|RET-06：两个时间事件重算到期日；不得直接用试玩时间起算|
|私人搜索 / 私密|本人最近 10 条关键词和时间；仅本人|每条发生起最多 90 天|RET-07：第 11 条淘汰、到期删除、清空立即删除；游客载体及去重 T-15 未定|

|备份 / 高度受限|业务快照；授权恢复人员|创建起滚动 30 天|RET-09：到期删除；恢复旧备份先重放已记录删除再恢复服务；T-11 实测|
|赛事核查、处罚、申诉 / 受限|必要证据及管理员决定；授权赛事处理人|最终发布、相关申诉结案较晚日期后 1 年|RET-10：清除个人材料，保留匿名统计及必要公开结果|
|公开获奖姓名 / 公开个人信息|获奖姓名及必要结果；公众|发布起展示 3 年|RET-11：到期下线姓名，保留不识别个人的赛事概况；更长公开须新决定|
|普通通知 / 私密|通知正文及已读状态；接收者|默认 180 天，可配置 30—180 天|RET-12：范围外配置拒绝；重要赛事、处罚、成绩另归档；起算事件须在通知实现时核对|
|身份、学号、账号资料 / 高度受限|人工核验所需；本人及授权管理员|注销处理及期限 T-08；认证细则 T-02|RET-13：公开页面/导出不泄漏；未决前不擅定无限保存|
|评论、作品、收藏 / 公开或私密|按作品权限和本人访问|收藏注销即删；其余注销行为 T-08|RET-14：收藏删除；评论作品按正式决定处理|
|游戏本地存档 / 浏览器私有|每作品来源专属；该作品|无云端存档；清档与迁移 T-16|RET-15：跨作品/主站不可读；不能因原型重载保留推定正式重启规则|

通用设计：数据记录携带分类、起算时间、到期时间及必要关联。清理任务批次执行、可重跑，日志只留任务数量/状态，不复制待删正文。月和年按日历单位，不私自换算成 180/365 天；精确时区和月末口径在实现前明确。

RET-16：主动清空或删除请求先清理无需继续保存的数据。确需暂停清理的记录必须关联正在处理的申诉、安全事件或明确保存要求，记录原因、批准人、复查日期；禁止整库无限期暂停。事项结束后恢复原到期计算，已过期立即进入清理队列。

RET-17：删除账本与备份分离保管、最小化记录；恢复后先重放删除，再校验公开姓名下线及档案期限。账本本身的最小字段和保留范围在 T-11 演练设计时确认，不将其变成新的个人信息副本。

RET-18：开发/测试只用合成数据，禁止复制真实学生资料；各类导出按角色脱敏并审计。供应商删除、不训练约束需合同与接口实测，当前均未验证。
