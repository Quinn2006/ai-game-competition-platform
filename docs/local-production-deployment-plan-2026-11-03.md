## 一、目标架构与权限边界

```
访客浏览器
    │ HTTPS
Cloudflare
    │ 加密 Tunnel
Windows：cloudflared 独立服务
    ├─ 主站公开域名 → 主站 Node.js 服务
    └─ 试玩公开域名 → 试玩 Node.js 服务
                         │
                   受限授权查询通道
                         │
                      主站授权
                         
主站 → PostgreSQL
主站 → 上传暂存、审核、发布存储
受限校验进程 → ZIP 校验、ClamAV 扫描
试玩 → 仅可读取允许分发的游戏资源
```

不对公网开放原始应用端口、PostgreSQL、扫描器和管理控制通道。Tunnel 由本机向外建立连接，不以开放家庭路由器入站端口为前提。

主站和试玩优先使用不同注册域；只有一个自有域名时，需将域名隔离方案列为待确认项，不默认为两个子域已经满足最强隔离要求。

拟保留内部网站端口 4320、试玩端口 4321、PostgreSQL 55440、ClamAV 3310；实施前检查冲突。公开访问统一使用 HTTPS 域名，公开 URL 不再决定本地监听地址。

| 身份/服务 | 允许权限 | 明确禁止 |
| --- | --- | --- |
| Tunnel 服务账号 | 读取自身 Tunnel 凭据，连接网站和试玩入口 | 读取数据库、作品目录、主站密钥 |
| 主站服务账号 | 业务数据库最小权限、业务文件操作 | 数据库超级用户、修改服务配置 |
| ZIP 校验账号 | 读取指定待检材料、写校验结果、访问扫描器 | 主站密钥、数据库凭据、任意网络访问 |
| 试玩服务账号 | 读取受控分发目录、调用专用授权通道 | 数据库连接、修改作品、读取审核原件及备份 |
| PostgreSQL 服务账号 | 数据库目录 | 网站代码写入、作品及 Tunnel 凭据 |
| 备份身份 | 备份所需数据库读取、文件读取及备份目标写入 | 公网请求处理 |

试玩与主站采用不同 Windows 非管理员账号、不同进程和明确 NTFS ACL。试玩使用 Windows Job Object 限制内存、CPU 和进程树；不允许子进程逃离限制。Job Object 负责资源控制，账号及 ACL 负责权限隔离，两者不能互相替代。 微软 Job Objects 文档

还需使用针对服务身份的网络限制阻止试玩连接数据库及无关网络；不能把"没有数据库密码"当作网络隔离证明。同机方案仍共享 Windows 内核，不宣称具备虚拟机级隔离。

## 二、生产上传与私有存储

采用本地 NTFS 私有文件存储，复用既有存储接口，不强制引入云对象存储，也不取消生产安全校验。

拟议布局继续沿用 data/submissions：

```
data/submissions/production/
    incoming/       分片、未完成上传
    quarantine/     待检、失败或隔离材料
    review/         通过技术检查、待业务审核的原件
    release/        批准发布的不可变原件
    serving/        供试玩读取的派生静态资源
```

serving 只包含可分发资源，不含投稿资料、数据库信息或账号信息。评委预览资源使用单独受控区域和授权类型；不能把全部 review 目录授权给试玩账号。

上传链路：
1. 登录并验证作品归属，创建绑定用户、作品的上传会话。
2. 浏览器将 ZIP 分片上传，建议初始分片大小为 8MiB。
3. 服务端流式写盘，限制单片大小、总量、并发、会话数量及磁盘占用。
4. 分片按编号和摘要幂等接收；支持重试、查询进度和恢复。
5. 合并后重新计算完整摘要，验证实际总大小。
6. 将校验任务交给受限进程；完成 ZIP 检查、病毒扫描及现有审核流程。
7. 批准后生成不可变发布资源，最后提交发布引用。
8. 未完成、失败或重复提交不会生成可试玩版本。

200MB 的精确字节值需在实施前统一：本计划暂按 200,000,000 字节解释，界面、服务端、导入工具和测试使用同一值；如果原需求指 200MiB，则统一为 209,715,200，不能混用。

压缩后上限改为 200MB，不自动同步放大解压上限、文件数或外部资源权限。现有解压上限等参数另做兼容性验证。ClamAV 的流式扫描、文件大小和递归扫描限制也必须匹配，超过扫描能力时明确拒绝，不能视为扫描通过。

文件与数据库不是同一个事务，因此增加明确状态及恢复规则：临时写入 → 完整校验 → 原子重命名 → 数据库确认；重启时核对未完成状态，禁止把孤立文件自动发布。

## 三、试玩服务拆分

当前 [服务入口](D:/AI-project/Codex-project1/backend/src/server.mjs) 在同一进程启动主站和试玩，必须拆开。

拟新增独立试玩入口，将 [现有游戏 HTTP 模块](D:/AI-project/Codex-project1/backend/src/modules/uploads/http.mjs) 分成：
- 主站：上传、版本管理、发放试玩授权、评委权限检查。
- 试玩：接收授权凭据、验证资源访问、返回静态资源。
- 内部授权通道：仅接受受信试玩服务身份，只返回当前请求所需的版本和资源许可。

保留每次访问检查撤回、下架、评委权限的语义，不能仅换成长效签名链接后失去撤销能力。授权服务不可用时拒绝分发；授权通道使用本机受限命名管道或同等可验证身份机制，不直接暴露公网。

游戏 ZIP 的解压和解析不再发生在试玩请求路径。资源预先由受限校验进程生成，试玩只读分发，减少压缩包攻击影响主站的机会。

继续保留：
- 浏览器 sandbox、CSP 和敏感浏览器能力限制。
- 精确 Host/Origin 校验。
- 不向游戏域发送主站 Cookie。
- 不把游戏脚本作为服务器端代码执行。
- 日志不记录完整试玩令牌、会话或上传凭据。
- 关闭业务缓存及离线缓存，避免关闭入口后仍从 CDN 获取受控内容。

## 四、每天启动与关闭机制

采用一个可重复执行的生命周期控制器，统一管理 Windows 服务；不分别堆积互相不知状态的启动脚本。

状态定义为：

```
STOPPED → STARTING → READY → OPEN → DRAINING → BACKING_UP → STOPPED
```

任何关键依赖异常进入 FAILED_CLOSED，保持公网关闭。

Windows 支持将 cloudflared 注册为服务，但启动与恢复策略须由平台时段控制约束，不能默认开机就公开访问。Cloudflare Windows 服务说明

| 时间/事件 | 计划行为 |
| --- | --- |
| 08:00 | 启动数据库、扫描器、校验进程、主站和试玩 |
| 就绪检查全部通过 | 启动 Tunnel，允许公网请求；若准备耗时，开放会晚于 08:00 |
| 21:50 | 页面显示即将关闭提示，上传界面明确续传规则 |
| 22:00 | 主站和试玩同时拒绝新业务请求，停止 Tunnel，结束公网访问 |
| 随后 | 排空或安全中止剩余工作，停止业务写入，备份，再停止数据库及其他服务 |
| 全部检查通过 | 输出"服务已停止，可以关闭电脑" |

关闭过程具体要求：
1. 禁止新上传会话、新分片和新业务提交。
2. 已确认分片保留；未确认请求允许次日幂等重试。
3. 运行中的数据库事务在有界等待内完成，否则回滚。
4. 暂停并持久化未完成扫描任务；不可把被中止任务标记为成功。
5. 停止定时清理和所有业务写入者。
6. 创建一致性备份并验证。
7. 正常停止 PostgreSQL，确认进程退出和端口释放。
8. 检查受管进程树、文件写入和停机状态。

备份失败时公网仍保持关闭，并尽可能正常停库；但不能显示"备份成功"。界面区分"数据库已安全停止"和"最新异盘备份失败"，让用户知道是否存在额外恢复风险。

不默认执行 Windows 自动关机。服务异常退出后的自动重启也必须检查时段，防止 22:00 后重新开放。

## 五、开机及异常恢复

开机任务必须无需用户登录即可运行，但不会直接开放 Tunnel。
- 08:00 前开机：保持关闭，等待开放时段。
- 08:00—22:00 开机：执行恢复检查、依赖启动及健康检查，然后开放。
- 22:00 后开机：不开放公网；若上次停机未完成，只执行必要恢复与收尾。
- 异常断电后开机：先等待 PostgreSQL 自身恢复，再核对上传分片、发布中间状态、任务租约及备份完整标记。
- 时钟明显异常或无法确认时段：保持关闭，提示检查时间同步。
- 休眠恢复或网络重连：重新核对当前时段，不能沿用休眠前的开放状态。

软件任务不能保证完全关机的电脑在 08:00 自行开机。自动通电启动需要主板定时开机等硬件支持；本计划默认由用户开机，开机后自动恢复。

## 六、数据库、备份与恢复

保留 data/postgres 作为本机持久化集群，不搬迁或覆盖现有数据。正式业务使用独立 ai_games_production 数据库及最小权限角色，现有开发库保留。是否将开发数据导入生产，另列显式迁移任务。

保留生产数据库 TLS 验证要求，补充本机可信 CA/服务端证书配置；不得为了本地部署将生产 TLS 校验改成关闭。应用不持有迁移和超级用户凭据。

现有 [运行与备份脚本](D:/AI-project/Codex-project1/scripts/local-runtime.mjs) 写死开发库，必须改造或抽取公共能力，不能直接拿它操作生产。

备份方案：
- 每晚停止全部写入者后，执行 PostgreSQL 逻辑备份及作品文件备份。
- 保存版本号、迁移版本、数据库记录核对信息、文件清单和 SHA-256。
- 只有校验完成后写入"完整备份"标记；中断产物不参与恢复选择。
- 分片续传状态与对应文件一起备份，避免恢复后数据库认为分片存在而文件缺失。
- 备份加密；MFA 等解密所需密钥单独受控保存并纳入恢复演练。
- 本地备份后复制到另一块物理磁盘；同盘副本不作为灾备完成依据。
- 建议初始保留策略：每日 7 份、每周 4 份、每月 3 份，实施前按磁盘容量确认。
- 清理旧备份必须以新备份已验证、剩余保留份数达标为前提。

恢复必须先恢复到独立目标，验证通过后再安排切换；禁止覆盖运行中的主库。恢复后检查账号、MFA、作品引用、审核状态、分片及试玩，并使不应继续有效的旧访问凭据失效。

初始恢复目标：夜间备份方案的最大数据损失窗口约为一天。如果无法接受，需要另行增加日间一致性备份或 PostgreSQL WAL 归档及对应文件版本保留，不能宣称现方案零丢失。恢复耗时以演练实测确定。

## 八、本地与公网验收分界

| 可先在本地完成 | 需要域名/公网环境 |
| --- | --- |
| 生产配置、分片上传、私有存储 | Cloudflare 账户及域名接入 |
| 独立进程、账号 ACL、资源限制 | DNS、公开证书和 Tunnel 路由 |
| 本地 TLS 与 Host/Origin 模拟 | 实际 Secure Cookie、跨域试玩 |
| 真实 PostgreSQL、ClamAV 联调 | 中国大陆不同运营商实际连接 |
| 200MB 上传、异常包、断电恢复 | 真实网络下 200MB 分片上传与恢复 |
| 时段测试、停机及备份恢复 | 22:00 公网关闭与 CDN 缓存检查 |

中国大陆访问测试应覆盖电信、联通、移动及至少一种手机网络，记录页面加载、试玩首帧、上传成功率、重连和高峰期表现。通过标准在试运行前按实际并发目标制定；Tunnel 可连接不等于大陆访问效果合格。

## 九、执行顺序与上线门槛

1. 确认参数：200MB 字节定义、可用内存与磁盘、两个域名的安排、异盘备份位置、预计并发人数。
2. 完成本地生产基础：配置、数据库角色、私有存储、服务身份和资源限制。
3. 完成上传与试玩拆分：先保持安全语义，再接入分片和独立校验。
4. 完成生命周期与恢复：定时开关、异常开机、夜间备份、独立恢复演练。
5. 完成本地验收：全部回归、权限探针、资源压力和真实浏览器流程通过。
6. 经你确认后接入域名及 Tunnel：进行受限公网试运行。
7. 公网验收通过后开放比赛使用。

上线前必须证明：200MB 上传可用、试玩权限及资源隔离生效、22:00 能关闭两个公网入口、电脑重启不会越时段开放、备份确实能恢复。 任一项未通过，都不以减少扫描、关闭 TLS、共享管理员账号或放宽文件权限来换取上线。
