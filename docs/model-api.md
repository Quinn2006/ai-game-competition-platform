# 公告、通知与模型 API 配置

管理员在“公告”页直接查看公告、发布或编辑公告、置顶和撤回；在“通知”页设置普通通知留存期限。运营后台不再重复放置这两组管理表单。普通用户只显示原有公告和通知内容。

## 配置 AI 客服

管理员打开“AI 客服”，在“AI 模型接入”填写服务商的 HTTPS API 地址、模型名称和 API 密钥，再勾选“启用 AI 客服”。支持 OpenAI 兼容的 Chat Completions 接口；地址可填写包含版本路径的 Base URL，或完整 `/chat/completions` 地址。

- “验证并测试连接”使用当前表单发送测试请求，不保存配置；测试可能产生服务商费用。
- “验证并保存”保存配置，下一条客服请求即生效。两项操作都沿用管理员密码和两步验证。
- 已保存的密钥不回显；留空沿用旧密钥，更换 API 地址必须重新填写密钥。取消启用后保存即可停用模型调用。
- 只支持可解析到公网 IPv4 的 HTTPS 地址，不支持本机、内网模型或带查询参数的 API 地址。请求不跟随重定向，超时 15 秒，响应限制 128 KiB。
- 接口发送单条用户问题与固定的公开帮助提示，不传账号资料、管理权限或历史对话；不提供工具调用。

请求结构参考 [OpenAI Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)，使用 `store: false`、`stream: false` 和 `max_completion_tokens: 1024`。兼容服务商必须支持这些字段和文本响应。

## 数据与升级

新增迁移 `011_support_provider`，只增加配置表。升级前沿用现有逻辑备份流程；Windows 启动入口执行迁移后即可使用新表。服务端使用现有 `SESSION_SECRET` 加密 API 密钥，数据库备份恢复时必须保留同一密钥，否则需重新填写 API 密钥。已有配置时拒绝回退迁移，避免误删密钥。

平台继续按原规则清理本地普通对话和投诉。此接入不创建平台可管理的远端对话对象，也不会产生可供旧适配器删除队列使用的远端 ID。`store: false` 不能证明服务商不留日志、不训练或可同步删除；接入前仍须核实服务商政策，不能据此认定历史隐私验收已完成。旧适配器的删除重试机制保留。

本地验证使用合成密钥和模拟模型响应，不代表任何真实服务商已连通。
