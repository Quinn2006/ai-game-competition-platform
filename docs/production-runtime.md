# 生产模式核心业务运行链路

2026-11-11：接通 `APP_ENV=production` 的服务组装。本记录是代码和独立环境验证结果，不是正式生产部署完成声明。

同日后续：生产入口已要求独立运行配置 `ISOLATION_CONFIG`，主站/试玩/ZIP 校验拆成三个入口。当前行为、Windows 安装脚本和验证边界以 [生产运行隔离](production-isolation.md) 为准；下文原双监听器验收是拆分前的历史记录，不代表现行生产进程拓扑。

## 本次行为

- 生产模式使用已经配置的私有存储，启用上传、分块传输、扫描、审核发布、资料附件和试玩；无需也不允许启用开发专用的 `LOCAL_GAMES=1`。发现页能力接口同时报告支持试玩。
- `MAIN_ORIGIN`、`GAME_ORIGIN` 继续要求不同主机的 HTTPS 来源；生产试玩内部默认监听 `http://127.0.0.2:4321`，可通过 `GAME_LISTEN_ORIGIN` 指定 `127.0.0.2` 或 `127.0.0.3` 的 HTTP 端口。外部 HTTPS 来源不会作为本机绑定地址。
- 私有存储账号和 ACL 校验失败时拒绝启动。数据库迁移校验、数据库环境标识、存储就绪及 ClamAV 实际扫描探针通过后才打开监听器。主站成功监听且试玩已监听后才记录 `app.started`。任一端口启动失败，关闭已经打开的监听器和数据库连接池。
- `/health/ready` 在原有数据库、存储检查之外，检查生产扫描器和试玩监听器。运行中的依赖故障会返回 503；此接口本身不关闭 Tunnel，也没有实现定时下线控制器。
- 审核批准读取 review 文件、试玩读取 review/release 文件时传入数据库中的 SHA-256；审核批准还在写入 release 前核对字节摘要。攻击者即使同时替换文件和 `.meta`，也不能借此批准不同内容。
- 正常退出停止接受新请求，等待正在处理的 HTTP 请求和清理任务，再关闭连接池，并释放分块传输及试玩票据。10 秒后强制关闭剩余 HTTP 连接，CLI 在 15 秒未退出时以失败退出；这不是“断电安全”或备份完成承诺。

## 启动前提与现有入口

`start-local.cmd` / `start-local.ps1` 仍是本地开发与公网试运行入口，其 Public 模式并不等于 `APP_ENV=production`。不要只修改环境名后直接对现有开发主库运行。

生产启动使用现有 `npm start`，环境参数结构见根目录 `.env.example` 的生产示例。真正执行前必须准备匹配的生产数据库、服务身份、私有存储 ACL、证书信任和扫描器；启动程序不会创建账号、修改 ACL、执行生产迁移或启动 Tunnel。

生产数据库仍要求 `ai_games_production`、用户名以 `_production` 结尾、`DATABASE_TLS=verify-full`，以及全部 001—011 迁移和 `production` 环境标识。现有迁移命令继续拒绝生产迁移；没有通过改名或放宽 TLS 绕过这项保护。当前仓库只有本地 NTFS 生产驱动的可用实现；未注入供应商驱动的 object 分支会因存储未就绪拒绝启动。

本次没有读取、修改 `data/public-tunnel.json` 或 `data/cloudflare-tunnel-token.txt`，没有启动主库、发布到公网或推送 GitHub。
